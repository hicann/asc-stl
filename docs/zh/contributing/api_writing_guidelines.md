# ASC-STL API 文档编写规范

本规范用于新增或修改 ASC-STL API 参考页面。页面内容必须与公开头文件和已交付接口严格一致，不得引用私有实现路径、内部编号、实施进度或验证过程信息。

本规范参考 Ascend C 的 API 写作规范和资料贡献指南，并结合 ASC-STL 的标准库接口、Host/Device 调用位置和自动投影流程作出补充。

公开文档使用可由GitCode直接渲染的普通Markdown。不要使用`(name)=`形式的
MyST显式目标，也不要使用`{toctree}`等Sphinx/MyST指令；页面导航统一使用
普通Markdown链接、列表或表格。

## 页面组织

API 页面按以下顺序组织，其中“数据类型”和“关键特性说明”仅在适用时出现：

1. 产品支持情况
2. 功能说明
3. 函数原型或声明
4. 参数说明
5. 数据类型
6. 返回值说明
7. 约束说明
8. 关键特性说明
9. 调用示例
10. 关联 API

每个逻辑 API 使用一个页面。同一 API 的已交付重载分别放入独立的 C++ 代码块；页面一级标题必须与 API 入口 map 中的标题一致。类型、枚举、变量、概念和宏使用“声明”代替“函数原型”，并只保留适用于该实体的章节。

## 功能说明

功能说明应覆盖以下内容：

- 功能作用：接口完成什么操作；
- 用户价值：接口帮助调用方解决什么问题；
- 基本用法：典型调用方式，以及需要配合的其他接口；
- 头文件路径：使用该接口时应包含的公开头文件。

功能说明不展示“实体类型、命名空间、最低语言模式、可用位置”元数据表：

- 实体类型由标题、章节名称和声明表达；
- 命名空间通过完整限定名表达；
- 非默认语言门控写入功能说明或具体原型说明；
- Host-only、AI Core SIMD-only、AI Core SIMT-only 等调用限制写入约束说明；
- 不同重载的语言模式或调用位置不同时，写在对应原型下方。

标准库页面可以链接对应 cppreference 页面，但不得复制外部参考资料正文。引入新概念或依赖其他 API 时，应在首次出现处解释并增加相对链接；计算类接口在公式更便于理解时应给出公式，复杂数据布局或执行过程按需增加图示。

## 函数原型与参数

- 函数原型必须与公开头文件一致，包括函数名、模板参数、参数名、参数类型、返回类型、限定符和重载集合。
- 多个原型按调用场景分组，或使用无序列表分别说明；不同原型使用独立代码块。
- 模板参数和函数参数分表说明。
- 参数说明包含输入/输出方向、作用、取值范围、单位、生命周期、地址空间、对齐要求和适用的数据类型；只与单个参数有关的约束就近写入参数说明。
- 参数名使用公开声明中的语义名称，不使用 `arg1`、`arg2` 等生成占位名。

## 返回值与约束

- 返回值说明写明返回类型及不同返回值的具体含义；返回引用、指针、迭代器或非拥有视图时，必须说明其生命周期。
- 无返回值时直接写“无返回值”，不生成空表格。
- 多参数关系、调用位置、收敛调用、同步、资源所有权和对象生命周期等组合要求集中写入“约束说明”。
- 约束使用面向用户的中文术语，不保留内部合同、执行画像或未翻译英文描述。

## 调用示例

API 页面只展示理解当前接口所需的关键代码片段。完整工程放在 `docs/zh/examples/`，页面通过相对路径链接，不重复内嵌整套 CMake、Host 和 Kernel 源码。

示例须满足以下要求：

- 使用具体类型和具体实参，不用未实例化的转发模板代替真实调用；
- 使用完整限定名调用接口，不写 `using namespace asc` 或 `using namespace asc::std`；
- 说明输入参数、关键配置和复杂逻辑的设置原因；
- 接收并使用返回值，或检查接口产生的状态变化；不得只将调用结果转换为 `void`；
- 给出预期结果、断言或可判断的返回条件，使读者能够理解调用后的行为；
- 参数个数、类型和顺序与函数原型一致，代码符合接口约束；
- 不调用未公开的接口，不把示例绑定到无关的特定算子开发方式；
- Device 专属接口展示正确的 Kernel 上下文、地址空间和必要同步关系；完整工程存在时增加源码链接。

不同实体采用与其语义相匹配的示例：

| 实体类别 | 示例要求 |
| --- | --- |
| trait、concept、编译期常量 | 使用 `static_assert` 展示成立条件；必要时增加一个不成立的对照类型 |
| 普通值函数和算法 | 给出具体输入，接收结果并说明预期值或位置 |
| 容器、资源和生命周期接口 | 展示最小完整状态变化、所有权和清理顺序 |
| Device、原子、同步和异步接口 | 展示执行上下文、地址空间、参与者条件、同步关系和可观察结果，并链接完整工程 |

示例应保持聚焦。代码片段短并不表示不完整；只要它覆盖当前接口的关键输入、调用和结果，就不需要添加无关初始化、完整 `main()` 或构建脚本。

## 导航与文件

`../api/README.md` 是 API 文档入口 map。源码目录与导航层次保持一致，导航不超过五级，不同节点不得指向同一个 Markdown 文件。父节点具有独立索引页。目录和文件名使用可读的英文小写及下划线，不使用生成哈希。

新增、删除或移动 API 页面时，必须同步更新入口 map 和 API 列表。上述文件由公开文档投影工具从同一份数据生成，不应手工制造第二套索引。

公开仓以 `docs/` 下的 Markdown、示例源码和图片为文档交付源。修改 API 页时须同步核对公开头文件中的实际声明，并按正式文档项目的审核、链接和发布流程提交。完整示例源码位于 `docs/zh/examples/`。

## 提交前检查

- API、头文件和声明数量与接口清单一致；
- 必填章节齐全且顺序正确，没有空说明、元数据表或研发占位文字；
- 参数名、参数类型、返回值和示例与公开声明一致；
- 示例不包含 `using namespace`，并展示可观察结果；
- 完整工程只提供相对链接，不在多个 API 页面重复内嵌；
- 页面不包含私有路径、内部编号、实现进度、验证术语或未翻译英文约束；
- 文档投影、公开内容、目录结构、相对链接、示例登记和适用代码片段检查全部通过。

`docs/` 只保存按语言组织的公开 Markdown 资料、示例和图片。正式网站的构建与发布由接收文档的项目执行，不在 ASC-STL 仓内维护第二套生成后的 HTML 文档或内部合同投影工具。
